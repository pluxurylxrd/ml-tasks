# Задача 4. Детекция объектов в видеообзорах товаров

## ТЗ

Находить товары в видеообзорах покупателей и продавцов для автоматической
проверки соответствия видео заявленной категории карточки

Вход - видеофайл (MP4, MOV, AVI, MKV)
Выход - список найденных объектов по кадрам, метрики по ролику
и копия видео с нанесёнными рамками детекций

## Преимущества выбранной библиотеки (Ultralytics YOLO)

- модель подключается одной строкой, веса загружаются автоматически
- встроенная отрисовка результатов: result.plot() возвращает кадр
  с рамками, подписями и уверенностью
- порог уверенности задаётся параметром вызова, без ручной фильтрации
- названия классов хранятся в модели и не хардкодятся
- opencv-python в составе зависимостей покрывает чтение и запись видео

## Принцип работы модели и причины её выбора

Модель: YOLOv8n (nano), веса предобучены на COCO

YOLO - одноэтапный детектор. Кадр проходит через свёрточную сеть один раз,
на выходе сразу формируются координаты рамок, классы и уверенность для всех
объектов. Изображение делится на сетку, каждая ячейка отвечает за объекты,
чей центр в неё попадает. Это отличает YOLO от двухэтапных детекторов
(Faster R-CNN), где сначала генерируются области-кандидаты, а затем каждая
классифицируется отдельно

Причины выбора:
- скорость: около 120–150 мс на кадр на процессоре против 1–2 с
  у Faster R-CNN, что принципиально при покадровой обработке видео
- вариант nano весит около 6 МБ, загрузка из кэша занимает 0.03 с
- 80 классов COCO включают бытовые предметы, пригодные для задачи
  маркетплейса: cup, laptop, book, bottle, backpack, umbrella, clock

## Структура датасета

Модель обучена на COCO: около 118 тысяч изображений, 80 классов
бытовых объектов и животных в естественной обстановке,
с размеченными ограничивающими рамками

Для оценки использованы 3 видеоролика со стокового сервиса Pexels
(свободная лицензия), по 8–14 секунд каждый, предметная съёмка.
Эталонный класс задаётся именем файла и считается постоянным
для всего ролика: book.mp4, cup.mp4, laptop.mp4

## Метрики оценки качества

- detection_rate - доля обработанных кадров, на которых найден хотя бы
  один объект. Показывает, теряет ли модель объект в принципе
- correct_rate - доля кадров, где найден ожидаемый класс. Основная метрика
- mean_confidence - средняя уверенность по детекциям ожидаемого класса
- label_switches и stability - число смен основного класса между соседними
  обработанными кадрами и доля переходов без смены. Метрика специфична
  для видео: в отличие от статичных изображений, здесь важна согласованность
  предсказаний во времени
- время обработки кадра

Разрыв между detection_rate и correct_rate диагностирует тип проблемы:
обе низкие - объект не обнаруживается, первая высокая при низкой второй -
объект обнаруживается, но классифицируется неверно

## Анализ ошибок

### Путаница близких классов

laptop.mp4 - единственный ролик с ошибками: 3 детекции класса tv
при 70 корректных детекциях laptop. Классы визуально близки: раскрытый
ноутбук с определённого ракурса даёт прямоугольный экран на тёмной рамке,
то есть признаки, совпадающие с признаками телевизора. Стабильность 0.979
означает, что подмена происходит эпизодически, на отдельных кадрах,
а не на протяжении участка видео

detection_rate 0.758 при correct_rate 0.737 показывает, что на четверти
кадров объект не найден вовсе - причина в смене ракурса,
при которой экран уходит из поля зрения камеры в конце ролика
